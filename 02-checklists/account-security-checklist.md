# 🔐 Account Security Checklist

## Overview

This checklist documents the account-security audit I completed for **Assignment #13**.

The purpose of the exercise was to evaluate important account-security practices, identify weaknesses, and establish stronger password and multi-factor authentication (MFA) policies.

The audit focused on password strength, password reuse, password management, MFA, login activity, recovery methods, and protection of important accounts.

---

| # | Security Check | Recommended Practice |

| 2 | Unique Passwords | Use a different password for every important account. |
| 3 | Personal Information | Avoid names, birthdays, phone numbers, and other easily guessed personal information. |
| 4 | Password Manager | Store credentials securely using a password manager rather than relying on memory or insecure notes. |

## 🔎 Account Security Audit

As part of the exercise, I reviewed important accounts using the checklist rather than publishing sensitive account information.

One account reviewed during the audit had a weak, reused password and did not have MFA enabled.

I remediated the weakness by replacing the password with a stronger, unique credential and reviewing the available security controls.

This exercise demonstrated how a simple account audit can identify security weaknesses before they result in unauthorized access.

## 🔑 Password Policy

Based on the audit, I developed the following password policy.

### Password Requirements

- Passwords should contain at least **14 characters**.
- Each account should have a **unique password**.
- Passwords should not contain easily guessed personal information.
- Long passphrases can be used to create credentials that are both strong and easier to manage.
- Passwords should be stored securely using a trusted password manager.

### Password Reuse

The previous **10 passwords** should not be reused.

Preventing password reuse reduces the likelihood that an old or previously compromised password will continue to provide access to an account.

### Account Lockout

After **3 failed login attempts**, the account should be temporarily locked for **15 minutes**.

This helps reduce the effectiveness of repeated password-guessing attempts.

---

## 🛡️ Multi-Factor Authentication Policy

Passwords alone should not be the only protection for important accounts.

MFA should be required for accounts that provide access to sensitive information or important services.

Examples include:

- Administrator accounts
- Faculty and staff accounts
- Student accounts
- School email accounts
- Remote-access or VPN accounts
- Financial accounts
- Accounts containing sensitive information

### Preferred MFA Methods

When available, the preferred methods are:

1. **Authenticator application**
2. **Security key**
3. **SMS as a backup method**

Authenticator applications and security keys provide an additional layer of protection beyond the account password.

---

## 📧 Primary Email Protection

The primary email account is especially important because many other services use email for password resets and account recovery.

If an attacker gains access to the primary email account, they may be able to attempt to reset credentials for other connected accounts.

For this reason, the primary email account should use:

- A strong, unique password
- MFA
- Updated recovery information
- Regular login-activity reviews
- Secure recovery methods

---

## 👀 Login Activity Review

Users should periodically review account activity for signs of unauthorized access.

Items to review include:

- Unrecognized devices
- Unexpected login locations
- Login attempts at unusual times
- Security alerts
- Changes to recovery information
- Password-reset activity that was not requested

Suspicious activity should be investigated promptly.

---

## ♻️ Old and Unused Accounts

Accounts that are no longer needed should not simply be forgotten.

Old accounts may contain personal information or credentials that could become a security risk.

Where appropriate, unused accounts should be:

- Closed
- Disabled
- Protected with a strong unique password
- Reviewed for stored personal information
- Removed from unnecessary connected services

---

## 🚨 Security Finding and Remediation

During the audit, I identified an example of poor account security involving:

- A weak password
- Password reuse
- No MFA protection

The account was remediated by creating a stronger unique credential and reviewing the account's security settings.

This demonstrated how account auditing can move beyond identifying weaknesses and lead directly to improved security practices.

## 🔐 Security Principles Demonstrated

This exercise demonstrates several important cybersecurity principles:

- **Defense in Depth** — MFA adds another security layer if a password is compromised.
- **Least Privilege** — Access should be limited to what a user requires.
- **Credential Security** — Strong and unique passwords reduce the risk created by credential reuse.
- **Account Monitoring** — Reviewing login activity can help identify unauthorized access.
- **Risk Reduction** — Old accounts, outdated recovery information, and weak authentication should be addressed before they are exploited.
- **Privacy Protection** — Sensitive credentials and account information should not be exposed in public documentation.
